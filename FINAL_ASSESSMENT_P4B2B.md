## Potential Issues Found

### ⚠️ **Issue 1: Condition Swap Clarity**

**Problem:** The narrative uses status flag condition swaps (`[IF WOUNDED:]`, etc.) but doesn't clearly indicate which flags apply to which paths.

**Impact:** Readers need to manually determine which condition swaps apply to their path.

**Example:** 
- Path P4B2-B should have: WOUNDED ✅, LIMITED_RESOURCES ✅, NO_ALLIES ❌
- But this isn't explicitly stated - you have to figure it out from the path description

**Recommendation:** Consider adding a status flag reference at the start of each scenario, like:
```
STATUS FLAGS FOR THIS SCENARIO:
- Paths P4B2-B, P3A2-B: WOUNDED, LIMITED_RESOURCES, SEEKING_REDEMPTION
- Paths P2B1-A, P3B2-A: EXPOSED, WOUNDED, SEEKING_REDEMPTION
...
```

### ⚠️ **Issue 2: Context-Dependent Flags**

**Problem:** Some flags (EXPOSED/FAMOUS, HAS_LEDGER, INNOCENT_BLOOD) depend on earlier choices that aren't immediately clear.

**Impact:** Readers might not know whether to read these blocks.

**Example:**
- `[IF EXPOSED OR FAMOUS:]` - Does this apply to P4B2-B? 
  - Need to check: Did you go public in earlier chapters?
  - If you came via Path 4B (alone, wounded fugitive), you probably didn't go public
  - But it's not explicitly stated

**Recommendation:** The PREVIOUSLY section could include these status flags, or there could be a status summary.
